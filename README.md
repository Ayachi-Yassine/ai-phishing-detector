# AI Phishing Email Detector

A machine learning component for a Security Operations Center (SOC) project. It classifies an email into one of three classes:

| Class | Meaning | SOC severity |
|---|---|---|
| `legitimate` | Normal email | info |
| `phishing` | Traditional, human-written phishing | high |
| `ai_phishing` | Phishing generated by a large language model | critical |

For each email it produces a JSON alert (verdict, confidence, severity, indicators, top terms, extracted URLs) that can be forwarded to a SIEM or dashboard.

## Why AI phishing needs its own class

LLMs produce fluent, grammatically perfect phishing emails that lack the typos and awkward wording that classic filters and users rely on. This project trains on both human-written and AI-generated phishing, so the model learns the stylistic differences as well as the usual phishing cues.

## Dataset

[PhishFuzzer](https://github.com/DataPhish/PhishFuzzer) (paper: *The Phish, The Spam, and The Valid: Generating Feature-Rich Emails for Benchmarking LLMs*, arXiv 2511.21448). Each email is labelled Phishing / Spam / Valid and by author (Human / LLM).

Preprocessing:
- Spam is removed (it is neither phishing nor legitimate).
- Only English emails are kept.
- Label mapping: Valid → `legitimate`, Phishing + Human → `phishing`, Phishing + LLM → `ai_phishing`.
- LLM-written *valid* emails stay in `legitimate`, so the model cannot learn the shortcut "AI-written = phishing".

Final dataset: 7,588 legitimate, 6,432 AI phishing, 1,063 human phishing.

The dataset is not included in this repository. Download it as described below.

## Method

- **Features:** word TF-IDF (1–2 grams), character TF-IDF (3–5 grams), and optional handcrafted features (URL count, shortened or IP-based URLs, urgency keywords, sentence-length variance, vocabulary diversity, punctuation density).
- **Classifier:** multinomial logistic regression with class weighting.
- **Evaluation:** 80/20 split **grouped by seed email**. The AI emails are rephrasings of seed emails, so a random split would put near-duplicates in both train and test and inflate the scores.
- **Ablation:** three variants are trained and compared; the best by macro-F1 is saved.

## Results

Test set: 3,021 emails never seen during training.

| Model | Macro-F1 |
|---|---|
| A) Word TF-IDF only | 0.9703 |
| B) Word + character TF-IDF (selected) | **0.9772** |
| C) Word + character + handcrafted | 0.9746 |

Final model (B), overall accuracy **98.25%**:

| Class | Precision | Recall | F1 |
|---|---|---|---|
| ai_phishing | 0.991 | 0.970 | 0.981 |
| legitimate | 0.980 | 0.993 | 0.987 |
| phishing | 0.949 | 0.981 | 0.965 |

Confusion matrix (rows = true, columns = predicted; order: ai_phishing, legitimate, phishing):

The main error type is polished AI phishing classified as legitimate (28 of 1,272), which is expected because such messages imitate normal business email.

```bash
git clone <this-repo-url>

```

## Usage

**1. Download the dataset** (into this folder):

```bash
git clone https://github.com/DataPhish/PhishFuzzer.git
```

Or download the ZIP from the PhishFuzzer page and extract it. The folder must contain `PhishFuzzer_emails_original_seed_v1.json` and `PhishFuzzer_emails_entity_rephrased_v1.json`.

**2. Train** (takes 2–3 minutes; prints the comparison, classification report and confusion matrix, and saves `ai_phish_model.joblib`):

```bash
python ai_phish_detector.py train PhishFuzzer
```

**3. Classify an email** (raw text or a path to a `.txt` file):

```bash
python ai_phish_detector.py predict "URGENT! Your account is suspended. Verify now http://bit.ly/3xYz"
python ai_phish_detector.py predict email.txt
```

## Limitations

- The AI-generated emails in the dataset most likely come from a limited set of LLMs, so the detector may not generalize to text from other models. Testing on emails from an unseen LLM is future work.
- The AI emails are rephrasings of real emails, so the AI class partly captures a "clean, polished" writing style.
- Very short, informal legitimate messages can be misclassified as phishing, because the legitimate training emails are mostly longer and more formal.
- Attackers can prompt an LLM to imitate human mistakes, which would weaken stylistic detection.
- Only English emails are supported.

## Future work

- Evaluate on AI phishing from additional LLMs.
- Add informal legitimate emails (for example the Enron corpus) to reduce false positives on short messages.
- Fine-tune a transformer (DistilBERT) and compare it with the linear baseline.
- Integrate with a SIEM (Wazuh, ELK or Splunk) and enrich extracted URLs with threat-intelligence lookups.
